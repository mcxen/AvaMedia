# 批量视频的原属性导出

批量旋转和批量裁剪默认选择“原格式 / 原属性”。混合导入 MOV、MP4 等视频时，分别沿用每个源文件的容器和扩展名。输出使用新文件名，不覆盖源文件。

画面处理保留视频编码类型、帧率、像素格式（位深和色度采样）及可用色彩标记，复制全部音轨、字幕和其他可封装轨道，保留章节与 FFmpeg 可读取的元数据。ProRes 同时沿用原 profile。视频重新编码，码率作为目标值，文件大小与画质可能变化；原容器中的私有信息不保证逐字节保留。缺少原编码器或无法使用原像素格式时明确报错，不自动改成其他编码或降低位深。

## 原属性模式的 GPU 编码

批量旋转、裁剪的原属性导出也参与自动 GPU 选择：视频编码器保持“自动”，高级设置开启“自动适配 GPU”。候选必须与源视频编码类型一致，并能保留其位深和色度采样；不会为了使用 GPU 将 HEVC 换成 H.264，或把 10 位降成 8 位。GPU 不可用或编码失败时重新选择原编码的软件实现，并在任务日志记录原因。

`SourceVideoGpu` 接入 NVENC、AMF、QSV 和 VideoToolbox 的原属性编码参数，目前接受 8 位和 10 位 4:2:0 源。GPU 输入使用 NV12 / P010，这是内存布局转换；输出保留源编码、位深、色度采样、帧率及色彩标记，其他轨道仍直接复制。对于 `yuvj420p`，显式转换保持 full range，并保留 `color_range=pc`。其他像素格式继续使用原属性软件路径。

2026-10-06 的运行中任务显示 GPU 自动适配已开启，但 FFmpeg 实际使用 `libopenh264`。原因是原属性分支在硬件候选筛选前就把“自动”改成了软件编码器。修复将软件选择延后至回退阶段，并恢复正确的软件编码器，避免硬件尝试失败后继续重用失败的硬件编码器。

处理中的队列状态显示当前选择的 GPU / 软件编码器，日志记录硬件尝试和回退原因。旋转、裁剪滤镜仍在 CPU 上处理；使用 GPU 编码不代表 CPU 占用归零。Fast Copy 不执行重新编码，因此不调用 GPU 编码器。本次仅完成相关客户端编译和静态诊断，未运行实机转码回归。

## 方向标记与指定格式

旋转的“Fast Copy（方向标记）”支持 MOV、MP4、M4V，只叠加播放方向，不重新编码视频、音频或字幕。支持源文件已有的方向标记；播放器需要支持 display matrix。含镜像的方向标记会拒绝此方式。MOV 章节数据由原章节信息重建，其他不能封装的轨道会报错。

实际改变画面像素的旋转、裁剪、缩放和滤镜必须解码并重新编码，不能直接复制压缩视频流。可选择 MP4、MKV、WebM、MOV、AVI 等指定格式并使用常规输出配置。

实现依据：[FFmpeg streamcopy、display_rotation 和像素格式选项](https://ffmpeg.org/ffmpeg.html)。

`AvaMedia.BatchRotateTests` 使用真实多音轨、字幕、章节、手机方向标记和 10 位 ProRes MOV，核对复制轨道的 SHA256、显示方向、帧率、色彩、位深、ProRes profile、混合格式队列与界面。`AvaMedia.BatchCropTests` 验证裁剪默认选项及指定格式的输出配置。
