# AI 任务端到端验收

2026-10-10，按用户要求在 macOS ARM64 上检查 AI 执行入口，并使用小图片和 4–8 秒视频运行真实任务。任务经 JSON 序列化后进入生产 `QueueService`、`MediaEngine` 和实际模型；没有替换推理、抽帧或导出结果。原生交互使用生产 Avalonia 窗口，主设置与任务列表使用独立测试目录。

实现提交：`8f03adc`、`4a9f7ec`。`final-source-manifest.json` 记录 28 个受影响源码文件的 SHA256；实际编译、执行的候选源码与这两个提交后的源码一致。

## 修复

- 自动转正检测加入共享任务队列。批量旋转和剪辑编辑器都能提交检测，关闭窗口后继续运行，完成后从任务重新打开结果并确认导出。窗口关闭与停止任务分开处理。
- 剪辑编辑、人物片段复核和导出选项使用非模态窗口，主窗口保持可操作。
- 修复首次运行删除尚未建立的 AI 缓存目录时抛错，影响标签 TXT、字幕和人物片段导出。
- 总结内部使用的临时语音识别不再遗留独立任务缓存。
- 自动字幕烧录在默认原始码率模式下改用质量编码，防止静态视频的极低源码率把字幕压掉；明确设置的输出码率仍保留。
- 标签任务保留识别、描述、保存各阶段的完成状态，并登记补帧阶段。
- 本地视频描述先分别观察采样画面，再按采样时间整理文字；需要时仍可调用实际取帧工具，显示逐帧进度。
- 线上模型请求结构化输出时解析独立的 JSON 代码块，避免供应商的 Markdown 包装使章节生成失败。
- 将所选输出语言传入总结步骤，短资料可以只写一句话，去掉固定 150–400 字的要求，并要求保留语音中的否定、条件和建议。

## 后台任务与原生交互

实际队列达到两个并发任务，运行中可以继续加入任务。等待模型时停止任务进入已取消状态，重新执行后完成实际推理。任务列表保存、重新读取成功，图像分数等结果保存在独立结果文件。

原生标签任务开始运行后关闭工具窗口，同一任务继续完成；期间能打开字幕工具，主窗口保持启用。任务结果重新打开可恢复分析配置及标签。剪辑编辑器内的自动转正也在关闭编辑器后继续完成，能从任务恢复检测结果并提交旋转导出。

快速剪辑的“下一步 → 返回编辑 → 下一步 → 开始导出”实际通过，片段仍为四秒，导出窗口打开时主窗口保持启用。导出任务完成且视频完整解码成功。

部分工具偏好仍走应用的默认存储。验收手动调整的标签采样帧数和“真人素材”已按调整前的原生界面记录恢复，其他标签偏好保持原值。剪辑导出偏好保存过本次输出目录；从主窗口重新打开导出时，目录会由主设置中的输出目录覆盖。

## 内容准确性与范围

本地视频描述最初把第六秒的纯色空画面误写成行人继续移动。核对应用实际取帧后确认图片正确；单帧模型能识别纯色画面，多帧描述出现内容串帧。首次非空文本检查只是执行成功证据，不能当作内容验收通过。

调整为独立观察后，开启和关闭补帧的两个真实任务都把第六秒识别为纯色空画面，开启补帧的任务实际触发了取帧工具。最终核对记录保存在 `caption-verification-report.json` 和 `caption-semantic-review.json`。模型仍会生成缺少依据的场所用途等细节，因此没有宣称画面描述已达到精确事实识别，也没有用这几例推导全部姿势、体位、人数或长视频的准确率。

额外使用同一语音视频运行“Whisper → 本地／线上文本模型 → 报告”，替代早期不匹配的外部字幕样本。本地总结初次把“应保持人声清晰”写成了“清晰度已改善”；调整提示后，总结正文保留了原意并输出英语，章节表述仍未完整保留要求语气，完整语义准确性未通过。线上初次因为 JSON 代码块包装未生成章节；修复后章节生成成功并保留要求语气，但正文仍把要求扩写为演示效果，英语设置下章节仍使用中文。初始记录和后续验证分别保留。

本次只验证 macOS 本机源码及原生窗口。烧录使用已有发布工具缓存中的 FFmpeg 8.1.3，系统 Homebrew 引擎缺少 libass 的失败记录保留；当前新发布包所用 FFmpeg 9.0.2、Windows 安装包没有在本次验证。Core ML 会话完成不代表每个算子都在 GPU／ANE 上执行。
