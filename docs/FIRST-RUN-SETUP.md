# 首次使用配置

Windows 和 macOS 的发布包通过独立原生启动器提供运行环境、界面风格和使用偏好向导，向导本身不依赖 .NET。

1. **运行环境**：需要下载时显示 .NET 8 与 ASP.NET Core 8，以及当前组件的下载、校验、安装状态和进度条。自动准备，失败时显示原因并提供重试；已就绪时直接进入皮肤选择。
2. **界面风格**：同时显示浅色、深色、Mac OS 9、Windows XP 的真实客户端缩略预览，点击选择。卡片使用统一留白、细边框、选中徽标、悬停和键盘焦点反馈；点击“放大预览”或双击卡片，在原生窗口中比较四种皮肤，缩放保持比例并显示完整界面。
3. **使用偏好**：选择默认输出目录、是否优先输出到源文件目录、语言、任务完成通知、GPU 自动检测、启动更新检查、减少动画。点击“完成并进入软件”后应用配置并启动原有软件；其它设置保留。

FFmpeg、FFprobe、yt-dlp 的清单、内置状态及重新安装提示不出现在首次引导中；已内置的 YuNet 也不出现在模型管理列表。需要另行下载的图片修复模型保留阶段、已下载体积、总量和百分比提示，失败时提供重试；已有模型的启动校验保持静默。

配置完成后保存 `setup-complete`，后续启动跳过向导，也不重复执行独立运行时预检。安装完成时的运行时校验保留。退出未完成的向导不会写入完成标记；已安装的运行时会被下一次向导直接使用。

原生启动器先原子写入用户数据目录的 `setup-pending.json`，最后提交 `setup-complete`。客户端在初始化任何窗口前合并这些选择到现有 `settings.json`；保存成功后删除待应用文件。用户数据目录为 Windows `%LOCALAPPDATA%\AvaMedia`，macOS `~/Library/Application Support/AvaMedia`。播放器打开参数和 macOS 首次启动期间收到的文件保持传递。

需要重新配置时可使用原生启动器的 `--setup` 参数。安装器的播放器注册／卸载维护入口不显示向导；截图工具的 `--capture` 入口在运行时已就绪时跳过向导，也不应用待处理配置。

## 预览资源

`Publish.ps1` 通过 `Prepare-SetupPreviews.ps1` 在对应平台打包时生成 `setup-previews/Light.png`、`Dark.png`、`MacOS9.png`、`WindowsXP.png`。客户端的 `--export-setup-previews` 入口创建独立临时配置，使用实际 `MainWindow`、皮肤资源、字体、图标、列表及自定义窗框，以 2 倍分辨率渲染固定的示例任务。示例不执行媒体处理；不读取用户队列、应用待处理首次配置、注册系统菜单、检查更新或下载模型。浅色／深色展示客户端区域；Mac OS 9／Windows XP 包含客户端实际自定义窗框。

四张图片由该版本源码生成，随安装包一起分发，减少皮肤代码与预览之间的偏差。资源生成超时、失败或缺图会阻止打包。Windows 原生向导用系统 WIC 解码 PNG，macOS 用 AppKit；两者显示预览都不依赖 .NET。缩略图和放大图共享同一图片，均保持比例、不裁切、不叠加改变皮肤配色的选中蒙层。缺少图片时显示“预览不可用”，不以手绘界面替代。

本次本地检查限定为客户端 Release 编译、macOS 原生启动器编译、语言资源和 diff 静态检查。Windows 原生编译由后台 Native bootstrap CI 执行；未运行界面、安装或媒体功能回归。
