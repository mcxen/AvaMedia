# 首次使用配置

Windows 和 macOS 的发布包通过独立原生启动器提供三步向导，向导本身不依赖 .NET。

1. **运行环境**：显示 .NET 8 / ASP.NET Core 8 是否就绪、使用位置及 FFmpeg、FFprobe、yt-dlp 的内置状态。缺少运行时时点击“安装运行时”，原生界面显示准备、下载、校验、安装及失败状态，可重试。使用当前用户缓存，无需管理员权限。
2. **界面风格**：同时显示浅色、深色、Mac OS 9、Windows XP 的原生绘制缩略预览，点击选择。预览使用与客户端皮肤相同的配色，表现窗口标题栏、导航、任务列表和进度条。
3. **使用偏好**：选择默认输出目录、是否优先输出到源文件目录、语言、任务完成通知、GPU 自动检测、启动更新检查、减少动画。点击“完成并进入软件”后应用配置并启动原有软件；其它设置保留。

运行时安装成功后仍留在向导中，用户可以完成皮肤与偏好选择。配置完成后保存 `setup-complete`，后续启动跳过向导，也不重复执行独立运行时预检。安装完成时的运行时校验保留。退出未完成的向导不会写入完成标记；已安装的运行时会被下一次向导直接使用。

原生启动器先原子写入用户数据目录的 `setup-pending.json`，最后提交 `setup-complete`。客户端在初始化任何窗口前合并这些选择到现有 `settings.json`；保存成功后删除待应用文件。用户数据目录为 Windows `%LOCALAPPDATA%\AvaMedia`，macOS `~/Library/Application Support/AvaMedia`。播放器打开参数和 macOS 首次启动期间收到的文件保持传递。

需要重新配置时可使用原生启动器的 `--setup` 参数。安装器的播放器注册／卸载维护入口不显示向导；截图工具的 `--capture` 入口在运行时已就绪时跳过向导，也不应用待处理配置。

本次本地检查限定为客户端 Release 编译、macOS 原生启动器编译、相关 PowerShell 语法和 diff 静态检查。Windows 原生编译由后台 Native bootstrap CI 执行；未运行界面、安装或媒体功能回归。
