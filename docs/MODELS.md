# 模型管理与视频分析 Beta

AI 重命名的候选词在 **选项 → 词库管理** 中管理；各重命名界面提供选择入口。词库、导入格式和处理可视化见 [WORD-LIBRARIES.md](WORD-LIBRARIES.md)。

选项 → 常规 → 开启 Beta 功能，应用后在视频分类中显示“保留有人片段 · Beta”。默认关闭。关闭 Beta 会隐藏入口，已有普通剪辑与合并任务继续使用现有队列。

选项 → 模型管理提供下载、取消、继续下载、SHA-256 校验和删除。模型保存在用户数据目录 `AvaMedia/models/`，按模型分目录；下载写入独立暂存目录，校验完成后发布。分析持有模型使用锁，下载或使用期间不能删除同一模型。YuNet 为内置资源，只展示状态。

选项 → 模型管理顶部的「模型下载源」可选 自动 / Hugging Face / ModelScope / HF-Mirror / 自定义，保存在设置中（`ModelSource`、`ModelSourceUrl`），应用后立即对新的下载生效：

- **自动**：系统界面语言为简体中文（zh-CN / zh-Hans）或时区为中国（如 `Asia/Shanghai`、`China Standard Time`）时，依次尝试 ModelScope → HF-Mirror → Hugging Face；其它地区依次尝试 Hugging Face → ModelScope → HF-Mirror。这样国内首次下载优先走直连速度更稳定的 ModelScope，海外仍以上游为准。
- **Hugging Face / ModelScope / HF-Mirror**：所选来源排在最前；失败或该模型没有此来源时，按自动顺序回退到其它来源。
- **自定义**：填写兼容 Hugging Face 仓库路径的镜像基址（可带路径前缀，不能包含凭据、查询参数或片段），排在最前，失败后同样回退。

ModelScope 只提供 `master` 分支，路径格式也与 Hugging Face 不同（`https://modelscope.cn/models/<组织>/<仓库>/resolve/master/<文件>`），因此模型清单为每个文件单独写出完整的 ModelScope 地址，不做域名替换；固定的文件大小与 SHA-256 校验保证下载内容与 Hugging Face 固定修订一致，上游若改动文件会被拒绝。目前提供 ModelScope 地址的模型：JoyTag、EmbeddingGemma 2。其它模型（Whisper、人物检测、LaMa、本地总结权重）只有 Hugging Face 路径，选择 ModelScope 时自动回退。原内置的第三方镜像 `hf-cf.northstar.cool` 来源不明，已移除。

环境变量仍然有效，并排在所选来源之前：`HF_ENDPOINT` 指定首选镜像，`AVAMEDIA_HF_MIRRORS` 追加其它镜像基址，以分号、逗号或换行分隔。重复地址只尝试一次；不保存有期限的 CDN 签名地址。

下载按轮次尝试候选源：一个源失败后立即换下一个，最多三轮，轮次之间短暂退避。每轮重新构造候选源；返回不可重试错误（例如 404、文件大小不符或 SHA-256 不符）的源不在本次下载中反复尝试。后续模型文件优先尝试本次已成功的来源。模型管理的进度、下载气泡和 AI 标签工作台显示实际来源名称（Hugging Face、ModelScope、HF-Mirror、GitHub 或自定义域名）和序号，悬停查看完整路径；最终失败列出各来源错误，完整错误链写入应用日志。

切换来源可以继续已有下载（`.part` 文件按 Range 续传），文件大小及 SHA-256 校验要求不变。GitHub 上的 llama.cpp 推理工具仍使用自己的下载地址。

在 PowerShell 中设置环境变量后，从同一窗口启动应用，变量值使用纯网址：

```powershell
$env:HF_ENDPOINT = "https://hf-mirror.com"
```

已运行的应用不会继承之后设置的环境变量，需要重新启动。

2026-10-09 ModelScope 验证：`https://modelscope.cn/models/fancyfeast/joytag/resolve/master/top_tags.txt` 下载得到 76752 字节，SHA-256 与清单一致；`model.onnx` 的 Range 请求返回 206 与 `bytes 366116000-366116153/366116154`。通过 `ModelStore` 选择 ModelScope 完整下载 JoyTag 时，在 120 MB 处取消后继续，从已保留的 `.part` 续传并通过 SHA-256 校验。

**导入本地文件**：每个模型行下方的「导入本地文件…」可选择文件或文件夹（文件夹最多向下查找 4 层）。按清单中的文件大小和 SHA-256 匹配，文件可以改名；匹配的文件先复制到暂存目录再按下载相同的流程发布。同名文件大小或哈希不符时提示「文件与模型清单不符」并列出文件名；缺少的文件会列出，已导入的部分保留在暂存目录，之后可继续下载其余文件。适合在浏览器或其它电脑下载后离线安装。

模型下载由应用管理，关闭选项界面后继续下载；重新打开模型管理可查看当前进度、取消或继续下载。模型下载、管理结果和失败进入 [右下角气泡通知](NOTIFICATIONS.md)，同一次操作原位更新进度。关闭气泡不会停止下载；停止和重试通过操作按钮执行，关闭选项后这些按钮仍有效。退出应用会停止下载，已下载的暂存数据保留用于下次继续。启动下载图片修复模型也使用同一通知中心，已缓存模型的启动校验不弹提示。

Google 模型下载完成后不会自动启用。自动剪辑窗口中可勾选“使用 EmbeddingGemma 2 语义辅助”。未下载时此选项不可用；任一种人体检测模型都可独立完成分析。所选检测模型必须全部下载完成，不会静默跳过缺失模型。视频不上传到远程服务；语义辅助在应用进程内用 ONNX Runtime 计算，不启动本地服务或子进程。

分析默认每秒采样 2 帧，默认使用轻量 NanoDet（约 1.07 MiB），也可单选或同时勾选全部三种检测。只解码需要检测的区间，每个模型按自身输入大小、颜色顺序和归一化方式计算同一画面。加载前对固定上游图中NanoDet 的空 Resize 输入做规范化，权重和下载文件保持不变，缓存按规范化图的哈希隔离。进度和结果显示实际模型、后端、每个模型的计算次数和有人帧数；GPU 初始化或执行失败时独立回退 CPU。

联合策略提供三种规则，模型分数不当作可相加的概率：

- **平衡检测**：多数模型超过各自阈值，或单个模型提供更强证据。
- **减少漏检**：任一模型超过阈值即保留，可能增加误检。
- **交叉确认**：至少两种且过半数模型超过阈值；单模型时使用该模型阈值。

默认不保留不确定片段。主动勾选“保留不确定片段”会保留弱证据，适合优先防止漏剪的场景。MediaPipe 使用更保守的 0.6 基准阈值，YOLOX 和 NanoDet 使用 0.35 基准，窗口阈值按相同比例调节。语义辅助只补充弱证据，不覆盖“交叉确认”规则。

扫描时先将满足合并间隔或前后余量相接的候选连接成大片段，只对大片段首尾进一步采样，细化至约 0.1 秒；内部短暂的有人／无人变化不单独细化。默认前后各保留 0.5 秒、合并间隔 1 秒，边界细化后再合并满足条件的区间并筛选最短时长。可修改采样频率（0.25–16 帧/秒）、阈值、前后余量、合并间隔、最短片段时长。相似画面只复用确定的有人结果，无人和不确定结果继续重新检测，避免小人物进入画面时沿用无人结论。

先设置检测与导出参数，再加入任务列表；每个视频一个任务，队列执行检测、默认接受模型结果并合并导出，无需等待分析窗口或逐段确认。支持任务停止、重试和重新编辑参数。可为每个视频填写或通过播放器标记免检测区间；这些区间直接跳过解码和模型计算，并从候选及前后余量中移除。默认快速排除黑灯和近乎纯色的无画面帧，检查源画面内容而非模型填充边框。正常的静止画面仍参与检测。只有一个保留区间时直接裁剪；原格式多段导出按源编码连接，重新编码每批最多处理 64 个区间再连接成一个文件。没有可保留片段时任务完成并标记跳过输出。详见 [人物检测队列](PERSON-CLIP.md)。

Beta 的采样可能漏掉极短出现的人物，小人物、遮挡、低光和画面中的人物海报也可能造成误判。已在一个约 23 秒的本地视频上实际运行人物检测，生成两个候选保留区间；不确定结果按任务参数处理；黑灯排除与降低采样频率可能遗漏暗处或极短出现的人物，本轮未执行素材检测、耗时对比或逐帧准确率校准。

## 关键词匹配重命名

开启 Beta 后，工具集 → 批量重命名显示“关键词匹配重命名 · Beta”。先在模型管理下载 EmbeddingGemma 2，再勾选此模式。输入关键词，以逗号、分号或换行分隔；可用 `海边=人在海边散步` 将短命名标签与较详细的匹配描述分开。最多 32 个关键词，命名标签须为有效文件名，最多 100 字符。

“匹配并预览”分析列表中的全部图片和视频；每张图片分析一帧，视频默认均匀采样 8 帧，相似画面可复用，独立画面每批最多 4 张。每个关键词的分数为采样画面与关键词描述的平均余弦相似度；选取最高分标签。达到最低相似度且领先第二个关键词达到指定分差时，自动勾选，否则显示“待确认”并保留原名。只有一个关键词时不应用关键词间分差。分数不是概率，默认阈值未经素材效果校准；短暂内容可能被采样遗漏，音频内容不参与此匹配。

默认模板为 `{keyword}_{index}`，保留扩展名；现有 `{name}`、`{parent}`、前后缀与文本替换仍可使用。序号按全部已勾选图片和视频的列表顺序排列。每行允许修改命名标签、手动勾选或排除；悬停查看全部关键词分数，修改后点击“预览新名称”。更改关键词或采样、匹配参数会清除旧匹配，需要重新分析。

分析支持停止并保留已完成候选结果，解码失败的文件不自动勾选。匹配过程中或匹配后源文件改变时，要求重新匹配。实际改名始终由“执行重命名”触发，复用原目录内改名、冲突检查、文件身份校验、回滚、撤销和队列路径更新。未开启 Beta 时语义入口与标签输入隐藏；普通重命名继续可用。模型由用户手动下载，分析在本地运行，不自动下载模型或上传素材。

## 图片 / 视频 AI 标签

开启 Beta 后，图片 → 图片 AI 标签，或工具集 → 媒体 AI 标签。图片与视频可混合添加；拖入主窗口时也可选择此工具。添加文件后点击“开始分析”，首次分析自动下载必需的 JoyTag 标签模型（约 367 MB），显示下载和加载进度；应用启动时不下载。底部提示按模型目录中的文件大小分别显示标签模型与语义模型的待下载大小。

模型管理中的“AI 标签模型加载”可选择打开工作台时预热（默认）或开始分析时加载。预热仅使用已经下载、当前分析设置需要的 JoyTag、成人内容和语义模型，不自动下载。空闲释放可选 1、5（默认）、15、30 分钟或保持到退出应用；计时从预热或分析结束后开始，工作台保持打开也会释放。工作台和模型管理分别显示未加载、加载中、预热中、已就绪、使用中和加载失败，附加载耗时、实际后端及释放倒计时。可停止或重试预热，也可手动释放空闲模型；正在分析的模型不会被手动释放。

JoyTag 固定支持 5813 个英文标签，包括人物外观、服装、场景和成人内容标签。图片按 4 张批处理，动图只分析首帧；视频默认均匀采样 8 帧，每批 4 帧，可复用相似画面。NSFW 与场景标签按采样峰值筛选，其他标签使用均值。默认阈值 0.4；有限采样可能遗漏短暂内容，分数未经此素材库校准。

关键词用逗号或换行分隔，每个关键词独立匹配；组合标签用 `+` 表示同时满足，如 `黑长发=black_hair+long_hair`。支持人物特征词库中的中文名称，如黑发、长发、纤瘦、腹肌、平胸、大胸、眼镜、坐着、微笑、阴毛等；其余可直接输入模型英文标签。通过“选择词库 / 类别”可按发色、头发、身体、乳房、眼睛、面部、配饰、动作姿态、神态表情、体毛分别选词，分析结果按类别显示已映射的中文标签与分数。未知标签会提示错误。所有达到阈值的匹配标签都参与文件名，不限制标签数量；关键词留空时使用全部达标模型标签。标签按分数排列，不因标签数量截取结果；名称过长时在预览中提示缩短名称。每行可手动调整标签与勾选。修改筛选条件后点击“筛选匹配”，再预览新名称。

分析只读素材，可导出标签 JSON。只有点击“执行重命名”才更新原目录文件名，使用现有冲突检查、源文件身份校验、回滚、撤销与队列路径更新。默认使用 CPU；GPU 可手动勾选，按平台尝试 Core ML / DirectML，编译或运行失败自动回退 CPU，每行显示实际后端。Core ML 可分派到 GPU、神经网络引擎和 CPU，不代表所有节点都在 GPU 上运行；首次编译较慢，需要磁盘空间保存缓存，后续分析复用缓存。本机 C# 路径已完成图片和视频的 Core ML 推理，但这批小样本没有稳定的整批提速收益。

NSFW 自动判断使用独立识别词库解释 JoyTag 分数：图片取该图分数，视频 NSFW 标签显示、关键词匹配和风险判断统一使用采样峰值。93 条中文标签包含后入、女上位、反向女上位、传教士等体位。显示“疑似 NSFW”“命中 NSFW 相关提示，未达风险阈值”或“未检出风险标签”，后者不代表安全。

「识别场景、照明与面部」默认关闭；已有偏好中保存的选择保持不变。勾选场景识别或所选词库含纯语义候选而语义模型未安装时，开始分析前弹窗询问「场景识别需要下载约 N MB 的语义模型，是否下载？」，同意后下载再分析；拒绝时本次只运行标签识别，并提示已跳过场景识别。加入任务队列时也在窗口内先询问；队列任务本身从不弹窗或下载，运行时缺少语义模型就跳过场景，并在 TXT/JSON 报告的「语义模型」一行和任务状态中记录。批量重命名的关键词匹配与自动剪辑的语义辅助同样先询问再下载：重命名拒绝时取消匹配，自动剪辑拒绝时只用人体检测模型分析。酒店与照明状态通过语义描述匹配，复用 JoyTag 已抽出的画面；不增加抽帧次数，不上传媒体。语义相似度、后端和时间证据在结果及 JSON 中独立记录，详见 [NSFW 标签识别](NSFW-REVIEW.md)。

### 语义模型实现与验证

语义模型使用 EmbeddingGemma 2 的 ONNX q4 导出，在 ONNX Runtime 1.23.2 中运行：Windows 先尝试 DirectML，macOS 先尝试 Core ML，创建或运行失败时回退 CPU，并在结果中记录实际后端与回退原因。分词器按 `tokenizer.json` 的 BPE（字节回退）规则实现；文本前缀为 `task: classification | query: `。画面按 Gemma 4 图像处理规则保持比例缩放（边长为 48 的倍数，双三次抗锯齿）、按 0–1 缩放后切成 16×16 图块，每帧使用 140 个视觉标记；视觉编码器输出与文本模型拼接，得到已归一化的 768 维向量。

旧版 Q8 GGUF 与 llama.cpp 文件不再使用，也不会自动删除；如需释放空间，可手动删除模型目录下的 `embeddinggemma-2` 文件夹（约 865 MB）。
