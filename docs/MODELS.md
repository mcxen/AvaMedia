# 模型管理与视频分析 Beta

AI 重命名的候选词在 **选项 → 词库管理** 中管理；各重命名界面提供选择入口。词库、导入格式和处理可视化见 [WORD-LIBRARIES.md](WORD-LIBRARIES.md)。

选项 → 常规 → 开启 Beta 功能，应用后在视频分类中显示“保留有人片段 · Beta”。默认关闭。关闭 Beta 会隐藏入口，已有普通剪辑与合并任务继续使用现有队列。

选项 → 模型管理提供下载、取消、继续下载、SHA-256 校验和删除。模型保存在用户数据目录 `AvaMedia/models/`，按模型分目录；下载写入独立暂存目录，校验完成后发布。分析持有模型使用锁，下载或使用期间不能删除同一模型。YuNet 为内置资源，只展示状态。

Hugging Face 模型下载支持多个镜像候选：`HF_ENDPOINT` 指定首选镜像，`AVAMEDIA_HF_MIRRORS` 追加其它镜像基址，以分号、逗号或换行分隔。两者都未设置时，优先原始 Hugging Face 地址，再依次尝试内置的 `https://hf-mirror.com` 和 `https://hf-cf.northstar.cool`；配置了镜像时，顺序为首选镜像、追加镜像、内置镜像和模型清单中的原始／备用地址，重复地址只尝试一次。镜像须提供与 Hugging Face 相同的仓库路径；支持基址包含路径前缀，不保存有期限的 CDN 签名地址。

下载按轮次尝试候选源：一个源失败后立即换下一个，最多三轮，轮次之间短暂退避。每轮重新读取环境变量并构造候选源；返回不可重试错误（例如 404、文件大小不符或 SHA-256 不符）的源不在本次下载中反复尝试。后续模型文件优先尝试本次已成功的来源。进度显示当前来源域名和序号，悬停查看完整路径；最终失败列出各来源错误，完整错误链写入应用日志。

镜像保留原始仓库、修订、文件路径和查询参数，文件大小及 SHA-256 校验要求不变，切换源可以继续已有下载。该设置适用于 Whisper、人物检测、JoyTag、LaMa、EmbeddingGemma 和本地总结权重；GitHub 上的 llama.cpp 推理工具仍使用自己的下载地址及模型清单中的备用源，不将其改写为 Hugging Face 路径。

在 PowerShell 中设置后，从同一窗口启动应用，变量值使用纯网址：

```powershell
$env:HF_ENDPOINT = "https://hf-mirror.com"
$env:AVAMEDIA_HF_MIRRORS = "https://hf-cf.northstar.cool"
```

已运行的应用不会继承之后设置的环境变量，需要重新启动。

2026-10-08 镜像查找记录：上述两个内置镜像对清单中固定修订的 NanoDet 文件 HEAD 请求返回 200 和预期的 1123958 字节大小；[Sufy](https://hf-cdn.sufy.com/) 同一请求返回 403，[hf-mirror.net](https://hf-mirror.net/) 返回 500，暂未内置。说明页见 [HF-Mirror](https://hf-mirror.com/) 和 [NorthStar 镜像](https://hf-cf.northstar.cool/)。这里只检查了响应头，没有完整下载或校验模型；所有实际下载仍须通过清单中的 SHA-256 校验。

模型下载、管理结果和失败进入 [右下角气泡通知](NOTIFICATIONS.md)，同一次操作原位更新进度。关闭气泡不会停止下载；停止和重试通过操作按钮执行。启动下载图片修复模型也使用同一通知中心，已缓存模型的启动校验不弹提示。

Google 模型下载完成后不会自动启用。自动剪辑窗口中可勾选“使用 EmbeddingGemma 2 语义辅助”。未下载时此选项不可用；任一种人体检测模型都可独立完成分析。所选检测模型必须全部下载完成，不会静默跳过缺失模型。视频不上传到远程服务；语义辅助使用仅绑定 `127.0.0.1` 的临时本地进程，带随机访问密钥，结束或取消时关闭。

分析默认每秒采样 4 帧，默认使用 NanoDet + MediaPipe（模型合计约 12.51 MiB），也可单选或同时勾选全部三种检测。视频只解码一次，每个模型按自身输入大小、颜色顺序和归一化方式计算同一画面。加载前对固定上游图中NanoDet 的空 Resize 输入做规范化，权重和下载文件保持不变，缓存按规范化图的哈希隔离。进度和结果显示实际模型、后端、每个模型的计算次数和有人帧数；GPU 初始化或执行失败时独立回退 CPU。

联合策略提供三种规则，模型分数不当作可相加的概率：

- **平衡检测**：多数模型超过各自阈值，或单个模型提供更强证据。
- **减少漏检**：任一模型超过阈值即保留，可能增加误检。
- **交叉确认**：至少两种且过半数模型超过阈值；单模型时使用该模型阈值。

默认不保留不确定片段。主动勾选“保留不确定片段”会保留弱证据，适合优先防止漏剪的场景。MediaPipe 使用更保守的 0.6 基准阈值，YOLOX 和 NanoDet 使用 0.35 基准，窗口阈值按相同比例调节。语义辅助只补充弱证据，不覆盖“交叉确认”规则。

扫描时先将满足合并间隔或前后余量相接的候选连接成大片段，只对大片段首尾进一步采样，细化至约 0.1 秒；内部短暂的有人／无人变化不单独细化。默认前后各保留 0.5 秒、合并间隔 1 秒，边界细化后再合并满足条件的区间并筛选最短时长。可修改采样频率（0.25–16 帧/秒）、阈值、前后余量、合并间隔、最短片段时长。相似画面只复用确定的有人结果，无人和不确定结果继续重新检测，避免小人物进入画面时沿用无人结论。

分析结果进入现有多片段编辑器，可以修改起止时间、删除和调整片段。输出可分别保存，或把每个源视频的保留片段合成一个文件。只有一个保留区间时直接裁剪导出；多个不连续区间才执行合并，最多 64 个片段。默认 Fast Copy 保留源容器和编码，边界受关键帧限制；需要滤镜或精确边界时可选择重新编码。没有可保留片段的源视频不生成任务；取消或分析失败不改动任务队列。

Beta 的采样可能漏掉极短出现的人物，小人物、遮挡、低光和画面中的人物海报也可能造成误判。已在一个约 23 秒的本地视频上实际运行人物检测，生成两个候选保留区间；不确定画面仍需人工确认，未执行裁剪导出或逐帧准确率校准。

## 关键词匹配重命名

开启 Beta 后，工具集 → 批量重命名显示“关键词匹配重命名 · Beta”。先在模型管理下载 EmbeddingGemma 2，再勾选此模式。输入关键词，以逗号、分号或换行分隔；可用 `海边=人在海边散步` 将短命名标签与较详细的匹配描述分开。最多 32 个关键词，命名标签须为有效文件名，最多 100 字符。

“匹配并预览”分析列表中的全部图片和视频；每张图片分析一帧，视频默认均匀采样 8 帧，相似画面可复用，独立画面每批最多 4 张。每个关键词的分数为采样画面与关键词描述的平均余弦相似度；选取最高分标签。达到最低相似度且领先第二个关键词达到指定分差时，自动勾选，否则显示“待确认”并保留原名。只有一个关键词时不应用关键词间分差。分数不是概率，默认阈值未经素材效果校准；短暂内容可能被采样遗漏，音频内容不参与此匹配。

默认模板为 `{keyword}_{index}`，保留扩展名；现有 `{name}`、`{parent}`、前后缀与文本替换仍可使用。序号按全部已勾选图片和视频的列表顺序排列。每行允许修改命名标签、手动勾选或排除；悬停查看全部关键词分数，修改后点击“预览新名称”。更改关键词或采样、匹配参数会清除旧匹配，需要重新分析。

分析支持停止并保留已完成候选结果，解码失败的文件不自动勾选。匹配过程中或匹配后源文件改变时，要求重新匹配。实际改名始终由“执行重命名”触发，复用原目录内改名、冲突检查、文件身份校验、回滚、撤销和队列路径更新。未开启 Beta 时语义入口与标签输入隐藏；普通重命名继续可用。模型由用户手动下载，分析在本地运行，不自动下载模型或上传素材。

## 图片 / 视频 AI 标签

开启 Beta 后，图片 → 图片 AI 标签，或工具集 → 媒体 AI 标签。图片与视频可混合添加；拖入主窗口时也可选择此工具。先在模型管理手动下载 JoyTag，不随启动下载，不自动启用。

JoyTag 固定支持 5813 个英文标签，包括人物外观、服装、场景和成人内容标签。图片按 4 张批处理，动图只分析首帧；视频默认均匀采样 8 帧，每批 4 帧，可复用相似画面。视频筛选使用各采样帧标签分数的平均值；它不是逐帧扫描，短暂出现的内容可能被遗漏。默认阈值 0.4，分数未经此素材库校准，需人工确认。

关键词用逗号或换行分隔，每个关键词独立匹配；组合标签用 `+` 表示同时满足，如 `黑长发=black_hair+long_hair`。支持人物特征词库中的中文名称，如黑发、长发、纤瘦、腹肌、平胸、大胸、眼镜、坐着、微笑、阴毛等；其余可直接输入模型英文标签。通过“选择词库 / 类别”可按发色、头发、身体、乳房、眼睛、面部、配饰、动作姿态、神态表情、体毛分别选词，分析结果按类别显示已映射的中文标签与分数。未知标签会提示错误。所有达到阈值的匹配标签都参与文件名，不限制标签数量；关键词留空时使用全部达标模型标签。标签按分数排列，不因标签数量截取结果；名称过长时在预览中提示缩短名称。每行可手动调整标签与勾选。修改筛选条件后点击“筛选匹配”，再预览新名称。

分析只读素材，可导出标签 JSON。只有点击“执行重命名”才更新原目录文件名，使用现有冲突检查、源文件身份校验、回滚、撤销与队列路径更新。默认使用 CPU；GPU 可手动勾选，按平台尝试 Core ML / DirectML，编译或运行失败自动回退 CPU，每行显示实际后端。Core ML 可分派到 GPU、神经网络引擎和 CPU，不代表所有节点都在 GPU 上运行；首次编译较慢，需要磁盘空间保存缓存，后续分析复用缓存。本机 C# 路径已完成图片和视频的 Core ML 推理，但这批小样本没有稳定的整批提速收益。

NSFW 自动判断使用独立识别词库解释 JoyTag 分数：图片取该图分数，视频风险取采样峰值，避免风险画面被采样均值稀释；普通标签筛选仍使用采样均值。显示“疑似 NSFW”“仅命中提示标签”或“未检出风险标签”，后者不代表安全。标签 JSON 同时包含自动判断及命中证据，详见 [NSFW 标签识别](NSFW-REVIEW.md)。

来源与固定版本：

- [OpenCV YOLOX](https://github.com/opencv/opencv_zoo/tree/main/models/object_detection_yolox)，Apache-2.0；ONNX 权重使用 OpenCV Hugging Face 修订 `d4938dfc9d4ec5d098bfa33e98b3f3345a236586`。
- [EmbeddingGemma 2 模型卡](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2)，Apache-2.0；[GGUF 转换](https://huggingface.co/ggml-org/embeddinggemma-2-GGUF)使用修订 `bfcd298762cc34d0357ece5ebdd31791a3a374d8`。
- [llama.cpp b11476](https://github.com/ggml-org/llama.cpp/releases/tag/b11476)，MIT；使用官方平台归档和 Release asset SHA-256。
- [LaMa](https://huggingface.co/opencv/inpainting_lama)，Apache-2.0；使用固定文件大小和 SHA-256。
- [JoyTag](https://github.com/fpgaminer/joytag)，Apache-2.0；[ONNX 权重及标签](https://huggingface.co/fancyfeast/joytag)使用修订 `6b7f16331a6ccf0fdce37d5a9564715f6e772b22`，大小与 SHA-256 固定，详见 `licenses/joytag/`。


## 人物剪辑专项端到端验证

`tests/AvaMedia.PersonClipTests` 仅验证人物剪辑：真实模型下载及 SHA-256、三种模型单独检测、三种联合策略、含人物/无人交替区间、远处移动行人、GPU/CPU 回退、取消、模型使用锁释放，以及分别导出和合并导出后的音视频时长与完整解码。`ui` 模式使用原生 Avalonia 窗口，验证多选、空选禁用、停止分析、策略切换清除旧结果、实际分析、多片段编辑器、导出设置与最终输出文件。验收素材来源为 OpenCV 的 `messi5.jpg`、`fruits.jpg` 和 `vtest.avi`，保存在本地 `artifacts/person-multidet/upstream/`，不随应用发布。它们验证功能链路，不代表对所有视频的精度保证。

```sh
dotnet run --project tests/AvaMedia.PersonClipTests -c Release -- core artifacts/person-multidet
dotnet run --project tests/AvaMedia.PersonClipTests -c Release -- ui artifacts/person-multidet
```

测试自动获取固定 OpenCV 4.12.0 素材并校验 SHA-256；结果写入 `report.json` 和 `ui.json`。用户未明确要求端到端验证时，不自行运行此测试。
