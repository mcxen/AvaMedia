# 保留有人片段

视频 → 保留有人片段 · Beta。先设置参数，点击「加入任务列表」，主窗口启动队列后执行检测和导出。默认接受模型结果，每个视频输出一个文件，不再要求分析后逐段确认。等待中或已停止的任务可以重新编辑参数和区间；队列支持停止与重试。

该工具使用[多页任务窗口](TASK-MANAGEMENT.md#多页任务与任务窗口)，流程为“分析处理 / 调整片段 / 合并确认 / 完成”：检测在“分析处理”页进行，完成后进入“调整片段”页编辑保留区间，再在“合并确认”页选择输出并合并。关闭窗口不停止队列；处理前的参数放在“分析处理”页上方的处理参数区，运行后隐藏。

“调整片段”编辑器也可作为独立窗口打开：在任务行右键“打开任务界面…”，或对已完成的旧任务从结果入口打开，两种入口使用同一编辑会话。

## 分析处理与检测帧回看

“分析处理”页显示实时检测帧、白色人物框、时间与帧号小签，以及有人 / 无人 / 未检测时间轴、保留比例条和片段列表。处理过程中保存检测帧、检测框和得分，页完成后可用“上一帧 / 下一帧”逐帧回看，显示帧时间、序号及实际得分，不自动播放；旧任务没有存档帧时显示“此任务未保存检测画面”。检测失败显示最后可读帧并保留中断处与部分结果，不提供调整片段。

## 调整片段

检测完成后进入“调整片段”页，编辑器为三栏布局：左侧片段列表（开关、序号、缩略图、检测依据与时长），中间预览，右侧检查器，底部为时间线。每次编辑都是一条命令，可撤销 / 重做，并自动保存到任务；底栏提交“下一步：合并确认”，也可“恢复检测结果”回到模型结论。源视频在检测后被修改时，页面给出警告并允许继续调整，但导出前需重新检测。

可执行的操作：

- 增删片段：在播放头新增手动片段、复制片段、把所选片段在保留与移除间切换；手动片段可整体删除。
- 起止点调整：检查器中输入或拖动时间线两端；时间线支持播放头定位、“设为起点 / 设为终点”、在播放头拆分、缩放与全片。
- 拆分与合并：单段可在播放头或任意时刻拆分，也可批量分割；相邻片段可“与上一段合并 / 与下一段合并”。
- 检测边界吸附：拖动边界时默认吸附到最近的检测边界，包括有分数记录时的首个 / 末个有人帧、无分数记录时的原检测片段边界、相邻片段边缘和免检测区间；拖动时显示吸附提示，按住 Alt 可临时关闭吸附。
- 排除区间：把所选片段或时间线选区“设为排除区间”，立即作为移除掩罩裁剪或拆分片段，并保存供下次检测使用。
- 输出顺序与效果：片段可上移 / 下移改变输出顺序；逐片段可设置速度、淡入淡出、裁剪、旋转、镜像、去水印与轨道选择，沿用快速剪辑的导出能力。
- 反转保留 / 移除：一键交换全部片段的保留状态。

片段列表完整显示起止时间，标签与置信度可换行；低置信度片段（已分析样本平均分低于阈值 + 0.1）单独标注。检查器显示所选片段的边界帧、检测依据与分数条。编辑器遵守检测参数里的最短片段长度，过短片段不会导致编辑器无法打开。

## 合并确认

“合并确认”页显示真实保留片段数、合并后时长与原片时长、保留比例条和按输出顺序的缩略图分页，并选择转场（淡入淡出，使用逐片段淡入 / 淡出，会重新编码）、输出格式与输出位置。开始合并后进度留在本页，关闭窗口不中断；原视频不会被修改。没有测量依据时不显示预计耗时与体积，直接拷贝只作为比例估计。合并完成后进入“完成”页，展示按媒体比例的输出预览、文件信息与逐页处理记录，文件可拖出复制。

## 参数与区间

默认使用 NanoDet，每秒采样 2 帧，开启 GPU 自动适配、相似画面复用、黑灯排除和无画面排除。高级设置可开启「保留手部特写」：人体模型没有保留的画面再用 MediaPipe Palm 192px 检查手部，适用于做饭、切菜等只露手的镜头。手部补检复用同一张解码画面，不新增视频抽帧进程。手部是独立保留证据，不参加人体模型的多数投票；该选项默认关闭：本轮厨房素材验证中找回了手部漏段，但也增加了无人物画面的保留，不能视为通用准确率改善；需要保留手部操作镜头时按素材开启。可选择 MediaPipe、YOLOX 和联合策略，并修改采样频率、检测阈值、片段余量、合并间隔、最短时长及不确定结果处理。降低采样频率可能漏掉短暂出现的人物；多模型会增加计算量。

GPU 自动适配优先尝试 Core ML / DirectML，模型加载或运行失败时回退 CPU。人物与手部模型的分数也会检查；加速后端运行成功但返回 NaN、无穷或无效概率时，改用 CPU 重试同一画面并在任务日志记录原因。每种模型使用独立的颜色、归一化、填充和张量布局；手部模型为 RGB [0,1] / NHWC，不能沿用人体模型的 NCHW 输入。输入张量在整个任务中复用，任务日志记录检测、导出耗时及后端。

选中一个视频，为它添加免检测区间。支持秒数、`MM:SS`、`HH:MM:SS` 和小数秒，也可点击「从视频标记…」，通过播放位置设定起点和终点。区间可以修改或移除；重叠及相接区间自动合并。各视频的区间独立保存，加入任务后随队列持久化。

免检测区间直接排除，扫描仅启动其余区间的解码进程。边界细化不读取排除区间，前后余量与短间隔合并也不能把排除区间重新加入候选。区间超出源视频时长时，任务在模型加载之前报错；标记整段免检测时不加载检测模型。

## 快速排除

模型计算前检查源画面有效区域，忽略缩放后添加的灰色填充边框。黑灯检查使用亮度均值、少量亮点比例和亮度方差；亮度阈值默认 8，范围 1–32。无画面检查仅排除亮度几乎没有变化的纯色或被遮挡画面。静止的房间和静止人物仍进入模型，不通过「没有运动」推断无人。

每次采样仍检查画面是否重新可见，避免跳过整个黑灯时间段后遗漏亮灯或人物出现。相似画面仅复用确定的有人结论，并至少每秒重新计算一次。队列进度与日志分别记录模型计算、复用、黑灯排除、无画面排除和手工免检测时长。

这些快速检查是启发式规则，可能遗漏极暗或几乎没有亮度变化的人物；可关闭两个排除选项或降低亮度阈值。参数尚未经过素材准确率校准。

## 导出

默认 MP4 重新编码，按检测区间精确剪辑。仍可选择「原格式 / 原码率」复制原编码，但起点受关键帧限制：多个短区间可能重复带入前卷画面，使输出超过检测保留时长，甚至超过源视频时长。需要按检测结果排除无人物画面时使用 MP4、MKV 或 TS 重新编码。

一个保留区间直接裁剪；多个保留区间合并成同一个输出。原格式连接按顺序处理区间，重新编码每批最多 64 个输入，再连接批次文件，避免一次打开大量解码器。任务只在全部步骤成功且源文件未变化后移动临时输出，不覆盖源文件；停止或失败会删除临时输出。没有可保留片段时显示「没有可保留片段，已跳过输出」。

人物检测任务共享一个模型执行通道，避免多个队列任务同时占用检测模型；一个任务进入导出后，下一个任务可以开始检测。媒体导出继续使用现有的编码与原格式连接能力。

## 连续解码与检测缓存

边界细化将二分定位可能读取的时刻一次性解码，每处边界启动一个短 FFmpeg 进程，再按原来的二分顺序计算模型分数。仍使用相同的 0.1 秒终止精度、检测阈值和前后余量。单处最多保留 63 张缩放画面，完成定位后释放，不保留整段视频帧。

完成的检测结果自动保存到本机缓存。源文件路径、大小、修改时间、全部检测参数与模型代码相同时，重试或重新导出直接复用确认区间；更换导出容器和编码参数不必再次检测。修改采样、阈值、黑灯设置或免检测区间会重新计算。缓存只包含结果和媒体信息，不保存视频帧，最多保留 64 份；缓存不可用时继续正常检测。

参考 Adobe 的公开资料：[Fast Mask](https://research.adobe.com/news/project-fast-mask/) 已应用于 Roto Brush 2 / 3，其[公开早期研究](https://research.adobe.com/publication/fast-video-object-segmentation-by-reference-guided-mask-propagation/)结合参考帧引导、遮罩传播和对象检测；[Roto Brush 文档](https://helpx.adobe.com/after-effects/desktop/roto-brush-and-refine-matte/roto-brush/roto-brush-refine-matte.html)说明已传播帧的推理结果会被缓存，冻结时复用。本次借鉴结果缓存与连续处理相邻帧的方式；AvaMedia 仍使用当前人物检测模型判断保留区间，没有接入 Adobe 的商用模型或像素级遮罩网络。

2026-10-09 按用户指定素材进行队列测速：同一视频前 180 秒、NanoDet、每秒 2 帧、阈值 0.35、原格式导出，原实现 14.48 秒，优化后 7.28 秒；两个输出的保留区间与文件 SHA256 一致。该结果包含模型加载、扫描、边界细化和导出，仅代表这台 Mac 与该素材，未人工逐帧评价检测准确率。

随后完整处理 6095.319 秒的 1920×1080 / 30 fps H.264、AAC 素材，实际走队列与合并导出路径，用时 283.52 秒：扫描 180.39 秒、边界细化 69.81 秒、导出 32.91 秒，其余为准备时间。模型确认 77 个区间，生成 6034.953 秒的 MP4，保留 H.264 / AAC 编码，源文件大小和修改时间未变。该素材没有触发黑灯或无画面排除，不能据此评价这两项规则的准确率；流复制输出边界仍受关键帧限制。

继续对同一素材优化连续边界解码与完成结果缓存：完整检测（不含导出）从 250.57 秒降至 191.44 秒，其中边界细化从 69.81 秒降至 26.63 秒，77 个保留区间逐一一致。整段缓存读取为 0.13 秒，没有模型重算；前 180 秒的完整队列再次运行用时 1.56 秒，其输出 SHA256 与原先相同。单次实测会受本机并行工作和缓存状态影响，不能将该素材的耗时作为通用性能承诺。

本轮完整缓存队列的导出未通过：SMB 源文件读取返回了全零的 H.264 数据包，并出现文件句柄错误；顺序复制到本机后也读到相同的全零包。该结果不能计为完整导出成功，上述 191.44 秒和 0.13 秒均只统计检测。
