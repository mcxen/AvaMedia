# 相似服装基础能力 · 2026-10-11

目标是先识别拍摄上下文，再按这次拍摄中可见的服装分目录。减少分割遗漏、词汇遗漏和取景变化造成的“待确认”，同时保留真实换装及归属冲突。

## 上游资料与实现选择

| 资料 | 相关结论 | AvaMedia 的处理 |
| --- | --- | --- |
| [MediaPipe Image Segmenter](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter)、[实际使用的 ONNX 模型卡](https://huggingface.co/senty-au/selfie_multiclass_256x256-ONNX) | 六类是背景、头发、身体皮肤、脸部皮肤、衣服、配饰，没有细分裙裤或内衣；ONNX 输入是 RGB、NHWC、0–1，输出是 logits | 核对现有缩放、输入和 softmax 正确；衣物种类继续使用 JoyTag，分割只提供区域证据 |
| [Google 多类分割模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Multiclass%20Segmentation.pdf) | 分割是粗粒度结果，遮挡、运动、光照会影响输出 | 强衣物标签能补充分割漏检；透明衣物及颜色冲突不使用不可靠的衣物图像特征 |
| [Fashionpedia](https://fashionpedia.github.io/home/index.html) | 服装种类、部件和属性是不同层次 | 统一维护衣物部件与属性；具体部件和大类分开比较，颜色冲突限定到相应部件 |
| [DeepFashion2 官方项目](https://github.com/switchablenorms/DeepFashion2) | 服装检索要处理遮挡、缩放及不同视角，同种类并不等于同一款 | 保留具体部件、颜色、细节和现有图像特征共同证据，使用视频多帧一致性；不只比较“大类相同” |
| [DINOv2 官方实现](https://github.com/facebookresearch/dinov2/blob/main/dinov2/models/vision_transformer.py) | 提供全局 token 和空间 patch token | 复用已保存的背景全局及局部特征，支持多视角与镜头移动，无需新增模型或再次编码 |

这些资料用于确定基础能力和模型边界，本次没有引入 Fashionpedia / DeepFashion2 模型或训练数据，也没有替换 JoyTag、MediaPipe、DINOv2 权重。

## 补齐的能力

- 共用 `OutfitVocabulary`：上装、外套、裙裤、制服、睡衣、连体衣、泳装、内衣、袜类、鞋帽、手套及附属饰物；支持颜色、花纹、材质、袖型和剪裁等已知正向修饰词。按实际安装的 JoyTag 词表生成特征，不把动作或否定词当成衣物。
- 归一同义部件，分开比较具体部件、大类和细节。强烈的明确缺失标签仅在超过 0.65 且领先相应衣物 0.15 时压低矛盾部件；未出现的标签不提供反证。
- 分割漏检时，强衣物标签仍能形成衣物帧；保留裤袜专用证据路径。优先使用明确衣物颜色，无可靠颜色则不写颜色目录名。相似度按实际可用证据分配权重。
- 多帧背景保留差异视角，局部区域跨位置匹配。文件最多四视角、组最多八视角，双向匹配尽量要求两个视角支持，继续使用完整链接聚类避免单帧串组。
- 特写可以继承有明确背景支持且衣物状态相容的组；没有背景或被其它组竞争的帧不强制计为该组，实际分歧仍保留。服装组内比较真实成员代表，而非仅比较平均向量。
- 无服装由显式标签、身体皮肤和衣物区域共同确认。缺乏信息的特写不推翻已确认状态；可见衣物仍阻止无服装归组。无服装按拍摄上下文另建目录，不做身份识别。
- 目录名称提高描述证据要求、去重同义部件，复用现有中文标签。普通服装补入共享标签分类；私密衣物继续受 NSFW 开关控制。

仍沿用现有模型会话、GPU 优先策略、CPU 预留设置、采样、逐文件检查点、队列和整理预览。没有新的推理会话或网络 AI 请求；已保存的原始模型特征可直接重新分组。
