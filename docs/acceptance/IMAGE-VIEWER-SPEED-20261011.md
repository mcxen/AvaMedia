# 天池看图打开速度与封面快速预览 · 2026-10-11

本机原生窗口实测通过：包含 20,001 张图片的目录没有增加当前图片的首帧等待；起点、终点和视频瘦身封面双击均直接打开单图快速预览，没有扫描目录。实测另外发现静态图片的中间 PNG 压缩耗时较大，本轮修复后，同一张 4K 照片的首帧中位数由约 2.5 秒降至约 0.46 秒。

## 环境、样本与计时口径

- macOS 15.7.1 / arm64 / Apple M4，Avalonia 11.3.22，Release 构建，原生 `UsePlatformDetect` 窗口及生产 Light 主题；没有使用 Headless。
- 基线为提交 `4e331fc7ada9790f3eef7f2581a0346e80a994a8` 的独立源码归档。复测在该归档中应用修复提交 `958b5ec` 的静态显示帧 PNG 压缩级别修改。
- 测量启动器使用生产 `ImageViewerWindow`、`EditorWindow`、`VideoSlimmingWindow`、`ImageViewport` 和编解码服务。仅在验收副本中把默认状态目录改到独立位置，并加入目录枚举、解码、绘图和快速预览的观测回调；没有改变扫描或解码的调度顺序。共享工作区的其他修改未参与本次原生测量。
- 图片为真实风景照片 `bing-Furada-20260816.jpg`，3840 × 2160，3,703,359 字节（约 3.53 MiB）。小目录包含 1 张；大目录包含当前图及该照片的 20,000 个硬链接，合计 20,001 个有效图片文件项。目录为本机 APFS，保留操作系统文件缓存，没有清空系统缓存。
- 普通打开计时从创建看图窗口之前开始，到包含图片的原生合成批次 `Rendered` 完成；同时记录 `ImageViewport.Render` 首次发出图片绘制命令、后台枚举开始 / 完成和列表应用时间。应用已启动，此口径不包含进程启动与系统输入识别耗时。
- 双击由桌面自动化在真实封面上执行。快速预览计时从生产 `ShowPreview` 接收到已有位图开始，到该窗口的原生图片渲染批次完成，不包含系统识别双击的时间。

## 普通打开结果

每个版本分别做 6 轮大小目录对比，交替打开顺序。中位数取第 2～6 轮各 5 个样本，首轮另列，避免把首次编解码器初始化与后续样本混在一起。

| 场景 | 修复前首帧中位数 | 修复后首帧中位数 |
| --- | ---: | ---: |
| 1 张图片的小目录 | 2504.9 ms | 469.5 ms |
| 20,001 张图片的大目录 | 2504.2 ms | 457.2 ms |

修复后首次打开看图窗口为 640.4 ms。大目录 6 次首帧为 446.6、421.8、484.3、476.2、443.4、457.2 ms。目录扫描自身约 115～245 ms，位于当前图片绘制之后；全部 6 次大目录样本的图片渲染完成时间早于扫描完成时间。

基线和修复后共 12 次大目录样本均满足：

- 先发出当前图片绘制命令，再启动目录扫描。
- 原生图片渲染完成后，目录扫描仍在继续。
- 列表补齐后仍选中 `current.jpg`，使用同一个已显示位图，没有再次调用当前图片解码。
- 扫描期间对已显示图片设置的手动缩放，列表补齐后保持不变。

原生界面另外观察到，当前照片与 `1 / 1` 状态先出现，随后状态更新为 `1 / 20001` 并补齐可见列表行。图像始终可见。图片源文件 SHA-256 在验收前后保持一致。

## 实测发现及修复

静态显示帧使用 `ImageCodec` 解码、应用方向和颜色处理，再通过 PNG 交给界面位图。默认 PNG 压缩耗时约 2212 ms，而 JPEG 解码约 43 ms；等待主要发生在显示用中间数据的压缩环节。

单张静态图片的显示帧改用 PNG 无损压缩级别 1。本样本中间 PNG 编码约 286～370 ms，临时数据由约 10.52 MB 增至约 11.89 MB。默认级别与级别 1 的解码后 RGBA 像素 SHA-256 完全相同，没有改变图片像素。修改仅作用于该静态显示帧路径。
