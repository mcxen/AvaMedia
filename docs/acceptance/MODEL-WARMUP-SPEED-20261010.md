# 本地大模型预热速度实测 · 2026-10-10

用户明确要求实际预热速度测试。本次限定两个默认本地生成模型，没有运行其它工具回归、内容质量验收、媒体输出或压力测试。

机器：Apple M4，16 GiB 统一内存，10 个逻辑 CPU；llama.cpp b11476，Metal。视觉模型为 Qwen3.5 4B Q4（含投影文件约 3.38 GB），语言模型为 Qwen3 1.7B Q4（约 1.28 GB）。全部已经安装，没有下载。

通过临时控制台调用生产 `ModelStore`、`LocalSummaryModelCache`、`LocalModelWarmupBudget`、`MediaEngine.Thumbnail`、`CompleteAsync`。预热顺序与总结工具一致：视觉模型轻量预热 → 语言模型轻量预热 → 选定视频后的单帧视觉预热。使用现有行人观察无声样片，首帧按 768 × 768 边界、不补边生成。

每个场景使用新的 .NET 和 llama-server 进程，包含首次完整文件校验；没有清空系统文件缓存或 Metal 编译缓存。这是进程冷启动数据，不能当作重启机器后的磁盘冷启动数据。各场景一次；100% 场景曾进行辅助进程检查，表格采用随后未进行该检查的确认轮次。

## 预热完成时间

| 场景 | 视觉模型轻量预热 | 语言模型轻量预热 | 画面预热追加 | 完整后台预热合计 |
| --- | ---: | ---: | ---: | ---: |
| 打开工具，10% 初始预算；轻量预热完成后选视频 | 36.09 秒 | 11.79 秒 | 10.87 秒 | 58.75 秒 |
| 打开即选视频，10% → 60%，5 秒渐增 | 9.39 秒 | 3.82 秒 | 9.98 秒 | 23.18 秒 |
| 100% 预算对照 | 4.43 秒 | 2.56 秒 | 6.55 秒 | 13.54 秒 |

没有选视频时，默认两个模型的轻量预热合计 47.88 秒；打开后马上选视频会让校验节奏升高，该部分降至 13.20 秒。100% 对照约 6.99 秒。用户开始正式任务会提升准备任务的优先节奏，这些后台完成时间不代表必须等待的界面前置步骤；本次没有另外测试预热中途点击开始。

默认未选视频时，视觉模型从 Loading 到 Warming 为 26.87 秒，之后 Warming 到 Ready 为 9.21 秒；语言模型分别为 10.65 秒和 1.13 秒。Loading 包含文件 SHA-256 校验及原生服务启动，Warming 包含实际一 token 图初始化和预算间隔。单次原生推理及其后限速等待没有单独打点，不能把 Warming 全部解释为 GPU 计算耗时。

## 资源与发现

使用生产 `SystemResourceMonitor` 每 500 毫秒采样整机 CPU/GPU，并只累计本次控制台直接启动的 llama-server 常驻内存。百分比含系统其它活动，常驻内存不是独立显存。

| 场景 | 整机 CPU 样本峰值 | 整机 GPU 样本峰值 | 本次 llama-server 常驻内存峰值 |
| --- | ---: | ---: | ---: |
| 打开工具，10% 初始预算；轻量预热完成后选视频 | 95.0% | 100.0% | 5.92 GiB |
| 打开即选视频，10% → 60%，5 秒渐增 | 79.1% | 100.0% | 6.10 GiB |
| 100% 预算对照 | 73.4% | 100.0% | 6.18 GiB |

- 当前比例控制后台工作节奏，不是原生加载或 GPU kernel 的硬占用上限；观察到了 100% 的整机 GPU 样本。
- 10% 初始校验预算明显延长准备，未选视频时尤为明显。100% 对照用于测模型准备速度，不作为低占用设置。
- b11476 默认日志级别 3 不输出模型层分配到 GPU 的信息，导致生产代码将已在 Metal 上运行的模型标为 CPU。独立原生诊断提高到级别 4 后确认 `MTL0 (Apple M4)` 和 `offloaded 29/29 layers to GPU`。已将生产启动日志级别设为 4；确认轮次两个模型都正确报告 `Metal / CPU`。早期三份 JSON 内的 CPU 标签保留为原始观测，不能据此认定使用 CPU。
