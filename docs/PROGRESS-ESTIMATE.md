# 转换任务预计剩余时间

运行中的转换任务在进度百分比旁显示 `预计剩余 HH:MM:SS`。每个并行任务独立估算；底部的已耗时继续表示本次队列的实际运行时间。

估算取实际进度与单调时钟的耗时，按最近 15 秒的处理速度计算：

`剩余秒数 = (100 - 当前进度) × 采样窗口秒数 / 窗口内进度增量`

它估计的是处理还要花多少时间。剪辑区间、速度设置决定的输出媒体时长仍由媒体引擎计算，两者分别显示。复杂画面、滤镜、硬件编码、磁盘速度和并行任务的资源竞争会改变处理速度，因此剩余时间会重新计算，可能增加或减少。

| 情况 | 界面行为 |
|---|---|
| 刚开始、有效采样不足 2 秒或尚无进度增量 | 显示“估算中” |
| 正在持续处理 | 每次进度回报及每秒刷新预计剩余时间 |
| 有进度后连续 5 秒不再前进，包括引擎停止回报 | 显示“进度暂未更新”；不保留过期倒计时 |
| 进度达到 99.9%，输出尚未关闭 | 显示“正在收尾”；不提前显示剩余零秒 |
| 编码器回退或进度重新开始 | 丢弃上一轮采样，重新估算 |
| 完成、失败或停止 | 清除剩余时间；保留完成状态或错误原因 |
| 重试 | 从零进度和新采样开始 |
| 尚在等待并发名额 | 保持“等待中”，不估算 |

剩余时间只存在于运行状态，不写入保存的队列。完成或停止后收到的旧回报不能恢复倒计时，也不能覆盖最终进度。下载任务使用下载引擎自己的速度与剩余时间，转换估算器不重复追加。

实现使用共享的 .NET `TimeProvider` 和队列模型，不依赖 Windows API。Windows 与 macOS 使用同一套逻辑；当前实际运行与界面验证来自 Windows，macOS 真机验证仍待完成。

专项验证：`dotnet run --project tests/AvaMedia.ProgressTests -c Release`。覆盖速度变化、重试、无效采样、停滞、并行任务、保存与取消，以及真实 FFmpeg 剪辑/裁剪/变速输出、浅深色任务列表和引擎静默后的界面刷新。完整回归使用 `./scripts/Verify.ps1 -Suite All`。
