## HandBrake 参考

查阅 HandBrake 当前主分支的 [Windows QueueService](https://github.com/HandBrake/HandBrake/blob/master/win/CS/HandBrakeWPF/Services/Queue/QueueService.cs)：同时运行数受 `allowedInstances` 限制，硬件编码需要取得资源令牌，完成后归还；未启用进程隔离时只运行一个编码实例。

其 [libhb/work.c](https://github.com/HandBrake/HandBrake/blob/master/libhb/work.c) 为解码、同步、滤镜、编码建立工作阶段，[libhb/fifo.c](https://github.com/HandBrake/HandBrake/blob/master/libhb/fifo.c) 用容量、条件变量和等待控制缓冲流动。这里借鉴的是有界资源与阶段协作，不能据此推断 HandBrake 会替不同编辑任务共享整段解码帧，也不把它的编码进程当成可任意抢占的时间片。

## 资源匹配

| 资源 | 可复用的调用 | 共享条件与边界 |
| --- | --- | --- |
| FFprobe 原始媒体信息 | 分类、服装时间信息、裁剪、分割、合并、压缩、队列封面 | `MediaProbeCache` 跨 `MediaEngine` 实例共享，键为规范化路径、长度、修改时间与探测工具路径。原始流信息共享，视频 / 音频轨选择由每个请求分别解析。最多 128 项、16 MiB 字符数据，单项超过约 2 MiB 不驻留。已移除原 4 路全局探测门闩，保留同源请求合并。 |
| 同源并发探测 | 不同工具同时打开或分析同一个文件 | 同键请求串行检查缓存，首个成功结果供后续调用复用。失败、取消、读取期间源文件变化不写入缓存；等待者自己的取消不终止另一个调用的探测。 |
| 图片与视频采样 PNG | 标签分类、服装分析、剪辑预览、多宫格、队列封面 | 图片也经过现有 `MediaPreviewCache` / `PreviewCacheStore`；文件身份、时间点、尺寸、轨道、补边等参数一致时复用。服装分析显式使用实际视频轨，和标签采样的 768 × 768 请求对齐。不同尺寸和时间点不会错误复用。 |
| JoyTag / NSFW / 语义模型 | 自动标签和自动媒体分类 | 继续复用现有按模型目录缓存的会话；JoyTag 每批、NSFW 每帧、语义图像每 4 帧释放租约。读图、抽帧、画面描述请求与结果整理不占模型锁。场景分类器只保留候选及标签向量，不保留可能已卸载的嵌入会话。 |
| 不同 JoyTag 批次设置 | 两个工具以不同 `BatchSize` 交替推理 | JoyTag 固定 batch 形状变化只重建 JoyTag；NSFW 与嵌入会话保留。模型文件或 CPU 策略变化仍按原规则失效。 |

探测缓存只保存在当前应用进程；帧缓存继续使用现有压缩缓存及空间限制。不同编辑滤镜、分割区间与输出格式不会共享可变的 FFmpeg 执行状态。最终输出仍由各任务独立分配、生成和发布。

## 接纳与交替执行

工具窗口已经通过非模态 `ToolExecution.ShowAsync` 与独立工作流打开，本次保留这条入口，不增加全局忙碌拦截。

`QueueService` 不按任务总数、工具类型或媒体 / 分析 / 下载类别设置接纳上限。用户启动的任务只要不与重命名、移动或文件保留发生冲突，就进入后台执行；后续加入的任务也直接接纳。暂停任务继续时直接恢复原执行器，不等待固定数量的调度位置。

已移除 `ParallelJobs` 设置、界面的每工具并发数控件和 MCP 的对应参数。关闭多线程只影响单个任务使用的线程数，不将队列变成串行。上一轮自行设定的编码后端 2 路令牌与探测 4 路令牌也已删除；硬件驱动和编码器实际可用能力仍由原有执行及失败回退路径处理。

没有任务数量上限不意味着共享资源可以无条件同时读写。同一模型会话继续按小批次互斥；同源同参数的探测和采样合并复用；现有预览生成门闩与缓存容量继续限制短期资源占用。CPU 预留保留单任务线程预算、较低进程优先级和按负载协作退让，不再折算成队列任务数量。这不是操作系统级 CPU / 显存配额。

分类在推理单元之间交还模型，其他已接纳的分类任务可以取得同一会话。模型加载、单次原生推理和已经启动的 FFmpeg 进程仍执行到安全边界；不会为了轮转强杀并重启编码。共享探测、缩略图和队列封面的锁内延后暂停，生成结束先归还资源，再允许任务停驻，避免一个暂停任务占住其他工具的预览资源。
