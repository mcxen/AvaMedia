# 视频总结 Agent Harness

调研日期：2026-10-13。目标是让本地与云端模型按需查看真实视频帧，避免固定画面描述与未经核实的转写主导总结。本轮范围为 Core 总结链路，不增加界面或改变用户选定的模型及供应商。

## 开源方案与选择

| 方案 | 官方资料中的能力 | 本次判断 |
| --- | --- | --- |
| [Pi agent-core](https://raw.githubusercontent.com/badlogic/pi-mono/main/packages/agent/README.md) | TypeScript 有状态工具循环、事件、上下文转换、工具执行钩子 | 借鉴循环与工具结果分离的设计；直接引入需要额外 JavaScript 运行时 |

| [Deep Agents](https://docs.langchain.com/oss/python/deepagents/overview) | `TodoListMiddleware` / `write_todos` 维护任务状态，基于 LangGraph 执行；当前文档的 v0.7 起计划能力按需启用 | 借鉴未完成事项的显式状态；本次不增加另一套运行时 |

实际依赖固定为 [Microsoft.Extensions.AI 10.10.0](https://www.nuget.org/packages/Microsoft.Extensions.AI/10.10.0)，该版本提供 net8.0 目标。代码真正使用 `FunctionInvokingChatClient` 和 `AIFunction` 执行工具；Pi 与 smolagents 只是设计参考，没有作为依赖或复制其源码。

## 原有断点

- `SummaryToolConversation` 和 `MediaCaptionFrameTool` 已用于画面描述功能，但视频总结没有接入。
- 短视频固定逐帧和近邻比较后，文本模型只能阅读描述；长视频同样先固定描述，再执行分段归纳。
- Whisper 结果直接成为 `transcript`，未保留与外部/内嵌字幕的可信度差别。VAD 只表明存在类似语音的声音，语言检测置信度不能证明转写正确。

## 当前实现（v6）

`SummaryAgentHarness` 把现有 `ISummaryModel.CompleteAsync` 适配为 `IChatClient`。模型每轮输出受 JSON schema 约束的单步决策，框架执行白名单工具。v6 将规划与像素感知分开：规划器读取结构化观察，感知请求只读取本次选定的真实 PNG，不混入旧图描述或转写。这不要求本地模型原生支持 `tool_calls`，也继续使用现有线上 Chat Completions 供应商配置。

`VideoSummaryCoverage` 沿采样计划或长视频当前窗口分配基础观察，默认 12 帧预算中先选 6 个时间点，保留其余预算供调查。小预算按实际数量处理，基础时间点上限为 6。`VideoSummaryFrameAgent` 在规划器运行前逐一发送隔离单图感知，结构化记录场景、主体、姿态与疑点。模型不能自己填写帧引用；程序根据实际输入绑定编号。随后允许模型调用：

- `inspect_clip(start,end,question)`：对最长 10 秒的片段采样最多 3 张实际画面，以一次隔离多图感知回答具体疑点；结果绑定全部实际输入帧。只有不同时间、相邻不超过 5 秒且感知明确支持变化时才生成 `sequence`；其余属于静态比较。
- `inspect_frame(seconds,question,region?)`：查看实际单帧或局部放大，返回自动绑定来源的感知结果。
- `read_transcript`：读取当前区间内相关时间段的文字及来源提示。文字用于规划，不进入像素感知。

工具只能访问当前任务的视频和当前分析区间。模型不能选择其他文件、执行 shell 或访问任意 URL。旧的 `record_*` 工具已移除，规划文本与问题不成为视觉事实。运行时限制轮数、图片数量、感知请求数和上下文，保留工具执行记录；最终自由文本不会绕过证据链直接成为总结。工具真实错误和用户取消继续传播，决策协议失败保留明确说明及可用画面观察。

工具决策使用带实际参数对象的联合 schema，而不是让小模型在字符串中再生成转义 JSON。完整画面重复请求会返回缓存 PNG 和原编号，不消耗新帧预算；同一帧集合与同一问题复用感知结果。基础观察自动执行，不能由规划器跳过；未保存任何可确认观察时不能以 `finish` 宣称完成，可以 `abstain`。完全没有有效对白或可确认画面时任务明确失败，保留部分产物。每次感知请求前保存实际输入帧编号和时间，格式纠正重附相同像素，失败不伪造事实。视觉资料不能支撑音乐、配乐等声音推断，相关候选须有文字来源并经过原资料核验。

短视频调查结果进入 claim grounding。要求内容总结时章节 schema 至少包含一章；正文和标题分别审核，标题被拒绝时以中性章节序号保留已通过的正文。全部正文被拒绝时，使用已审核事实和本轮正文拒绝原因做一次有界语义修复，仍不通过则明确失败。结构格式纠正与语义修复分开，不放宽事实审核。`report.json.GroundingTrace` 与 `grounding-trace.json` 保存各阶段结构候选、原始/展开引用、审核决定与原因；失败和取消同样保存，拒绝计数不再等最终章节成功后才更新。只导出 schema 允许的候选字段，不收集隐藏推理。

长视频在每个分析窗口完成同样的视觉调查，再进入既有 map/reduce 与核验流程；检查点包含 Harness 版本 6 和分析重点，语音原文与用于总结的证据分开保存。本地视觉和文本模型顺序使用现有租约，避免为调查同时加载第二个本地模型。短视频新增的 `GroundingTrace` 不替代长视频原有分段检查点。

本地 `LocalSummaryModelId` 可显式设为 `summary-qwen35-abliterated`，由 Qwen3.5 4B 做最终归纳和引用复核。视觉模型可以处理纯文字请求，无需固定将 4B 的观察交给 0.8B 总结。长视频 4B 预算对应本机实际 16K 上下文，视觉阶段结束后再获取总结租约；报告保存实际模型 ID。桌面预热沿用实际所选模型并去重，选择 4B 总结时不额外预热 0.8B。第三轮全 4B 实测未生成通过证据校验的章节，因此保留现有 0.8B 默认值；可选 4B 的接入已完成，但不能宣称该配置通过语义验收。

[Qwen3.5 4B 官方资料](https://huggingface.co/Qwen/Qwen3.5-4B)将模型定义为带视觉编码器的语言模型，并公布语言与视觉指标；[0.8B 官方资料](https://huggingface.co/Qwen/Qwen3.5-0.8B)提供同系列小模型指标。官方模型成绩不能直接替代本项目所用量化衍生模型、禁用思考模式下的实测；本次改路由和工具接口后复测属于整条链路验证，不是控制变量的模型能力基准。

`VideoSummaryTranscriptPolicy` 保留原始字幕导出，只从总结证据中排除明确非语句标记、病理重复及已有 VAD 明确不支持的转写。无 VAD 数据不视作无语音。Whisper 证据标记为 `speech_transcript`，事实提炼、归纳和核验保留语音来源及不确定性。零散或无关的识别语句不应覆盖画面的场景、主体和主要活动；正常连贯的教学或叙述语音仍可总结。

## 能力边界与检查范围

Harness 提供重新观察和纠错的机会，不改变模型权重，也不能保证小模型的视觉语义或转写准确。当前未新增音频语义分类器，不能仅凭 VAD 判断音乐、广播或对话；因此不会声称已经可靠识别并剔除所有环境音幻觉。

初始实现按 `AGENTS.md` 只运行受影响项目编译与必要静态诊断。用户随后明确要求 GPT 6 luna 用 MCP 下载视频并验证本地模型，因此追加同一条 69.7 秒街头舞蹈视频的定向端到端验证，失败与复测保留在[验收报告](../acceptance/VIDEO-SUMMARY-AGENT-LOCAL-20261013.md)。不新增自动测试或扩展界面、性能验收。用户提到的商场闲逛视频尚未提供，不能据此宣称该视频的总结质量已通过验收。

本地检查：`AvaMedia.Core` Release 构建通过，0 警告、0 错误；修改范围的空白错误检查通过。长链分段系统提示词与 schema 静态计数约 715 tokens，低于现有 1024 预留。Agent 的上下文边界另按字符估算，不等同于模型的精确 token 计数；传入图像复用现有 384 像素预处理，完整 PNG 单独保存，执行记录不内嵌图片数据。

用户随后要求云端验证，使用已配置的 Dots 模型对同一素材运行两次：首轮供应商超时；重试完成两次自主补帧和两次观察记录，但在最终归纳阶段遇到无效 JSON。详情见[云端验收报告](../acceptance/VIDEO-SUMMARY-AGENT-CLOUD-20261013.md)。这证明按需截图工具已实际使用，不能视为完整总结验收通过。实测还发现 MCP 部分结果未同步磁盘中的调用记录，已在 SaveInvestigation 中同步 AgentTrace；该诊断修复只进行相关编译检查，未新增云端运行。

## v5 计划、核验与纠正循环记录

根据本地遗漏结尾、重复观察，以及云端 JSON 解析失败的证据，进一步参考 Pi 的有状态行动/结果消息与完成钩子、smolagents 的计划/最终检查、Deep Agents 的任务状态，补齐共享执行链：

1. 每个工具决策携带简短 `plan` 和 `nextCheck`（各不超过 240 字），说明待查事项及可观察的检查目标。它们属于公开行动记录，不作为事实来源，也不要求或保存模型隐藏推理。
2. 每轮注入实际状态：已看画面编号、实际时间、是否裁剪、是否保存观察/不确定性、待核实总览图以及剩余预算。状态从真实执行结果计算，模型不能靠把计划写成“完成”来修改。
3. 默认最多 8 轮决策、7 次工具执行、10 次模型请求；决策格式最多纠正 2 次。工具失败、参数错误、返回结果和结束拒绝都进入有界上下文。小模型上下文优先保留完成条件和当前状态，压缩旧历史；磁盘执行记录保留原始步骤，不保存 PNG 的内嵌数据。
4. 初始总览图逐张有观察或明确不确定性，且至少存在一条观察，才能结束。结束检查失败给出具体缺失编号，预算允许时继续调查；预算不足时须明确放弃。可重新附上旧完整截图，裁剪另算新帧；完全相同的观察复用原编号，避免重复增加证据。
5. 内容表述、逐条 `supported` 审核、总结结构先检查完整 JSON 及当前 schema 的字段/类型/数量/长度。格式不合格时，同一模型按原资料、原任务、schema 和具体格式错误完整重生成一次。结构通过后才进入引用与语义审核，纠正不能跳过原审核；再次格式错误、拒绝、超时、IO 和取消均明确失败。

本次未更改本地模型原生 thinking 开关、权重、默认模型或云端供应商。公开计划和证据核验循环可以为模型提供纠错机会，但不代表更换为更强的模型，也不保证错误视觉描述会自动被识别。Harness 版本升至 5，长视频检查点据此失效重算。

这一轮在基于 `origin/main` 的隔离工作区完成 Core Release 构建，0 警告、0 错误，并通过本次修改的空白错误检查。未重跑媒体或云端推理。上方历史验收结论保持不变；新增循环能否改善同一素材的最终总结，尚未经端到端复测。

## 视频总结专用开源实践补充

2026-10-13 补充调研：用户进一步要求比较真正的视频总结项目。针对 AvaMedia 的判断是：以 **NVIDIA VSS 的分段观察和汇总管线**作为工程参考，以 **Microsoft DeepVideoDiscovery 的多粒度查看工具**补充主动调查能力。此选择是结合桌面工程约束的建议，不是跨项目质量基准结论。

| 项目 | 已核实的做法 | 对 AvaMedia 的取舍 |
| --- | --- | --- |
| [NVIDIA Video Search and Summarization](https://github.com/NVIDIA-AI-Blueprints/video-search-and-summarization) | 当前仓库包含长视频总结、快照/片段检索、MCP 与报告工具。其 [2.3 架构文档](https://docs.nvidia.com/vss/2.3.0/content/architecture.html)明确描述分块采样、VLM 描述、可选 ASR 与时间戳数据；[CA-RAG 文档](https://docs.nvidia.com/vss/2.3.0/content/context_aware_rag.html)先汇总批次再聚合全片。当前[总结工作流](https://docs.nvidia.com/vss/latest/agent-workflow-lvs.html)输出总结与带时间戳的事件，并提供片段链接。 | 首选工程模式参考。桌面版复用 FFmpeg、既有模型及本地结果存储，暂不引入其 Docker/GPU 微服务、图数据库及整套部署。旧版文档仅用于说明稳定的分段/聚合设计，不把旧模型配置描述为当前默认值。 |
| [Microsoft DeepVideoDiscovery](https://github.com/microsoft/DeepVideoDiscovery) | 实际源码 [dvd/build_database.py](https://github.com/microsoft/DeepVideoDiscovery/blob/main/dvd/build_database.py)提供 `global_browse_tool`、`clip_search_tool`、`frame_inspect_tool`；后者按时间范围向视觉模型发送多张实际图像。`dvd_core.py` 使用工具循环和最大迭代数。 | 最接近主动补看需求，借鉴“总览→找相关片段→针对具体问题精看”。其公开版全局浏览使用描述，`lite_mode` 仅使用字幕，均不能替代商场/舞蹈这类视觉场景的实际画面核对；论文云端模型成绩不代表本地 4B 能力。 |
| [claudetube](https://github.com/thoughtpunch/claudetube) | 下载、转写、缓存、按需提帧，MCP 提供帧、高清帧、场景等工具。 | 可参考缓存与工具接口。默认从转写开始的流程不直接解决无清晰口述视频，AvaMedia 仍应确保全片视觉覆盖。 |

下一步最有价值的工程工作是让程序保证基础证据覆盖，再让 Agent 对疑点执行定向调查：

1. **按片段观察。** 根据视频长度与场景变化形成带重叠的时间窗口；每段使用有序近邻帧，记录场景、主体、可见动作和不确定性。全片概述的输入是时间线事件，而不是服装/物体描述清单。
2. **保留证据来源。** 每条事件保存实际起止时间、帧编号、视觉/字幕/ASR 来源。ASR 内容不能自动成为视频主线；没有可用转写不能推断没有声音。VSS 的音频处理可按请求开关，但其公开文档不证明它已经解决环境音转写幻觉。
3. **带具体问题补看。** 提供类似 `inspect_clip(start,end,question)` 的能力，遇到“是不是倒立”“是否从站立变为坐下”再提高局部采样密度。工具运行时根据实际输入帧绑定返回观察的证据编号，减少模型把 A 图描述挂到 B 图的问题。截图说明发生矛盾时回到图像核对，而不是只让文本模型判断两份描述谁正确。
4. **逐层汇总。** 先片段事实，再章节，再全片摘要；保留每层可追溯的原证据。关键词、章节标题与正文同样需要依据。
5. **程序验证覆盖与执行，模型验证含义。** 计划字段和格式正确不代表看懂视频；必须分别报告任务是否完成、关键时间段是否覆盖、事实是否准确、噪声是否进入主结论。为最终归纳保存结构化候选、证据引用、保留/剔除状态及具体原因，避免只留下“没有有依据章节”而无法区分生成、引用或审核失败。模型判断不确定性是启发式信号，不能当作校准后的概率。

以上是调研阶段的改进建议。用户随后授权开发，v6 已接入本页“当前实现”描述的基础覆盖、隔离感知、片段回看和章节诊断。当前仍是离散图像采样，未部署连续视频理解、音频分类器或自动矛盾检测模型；不能把工具可用等同于模型一定能发现并解决语义错误。

GPT 6 luna 已完成同一素材的本地双 4B 和云端 Dots 各一轮 [v5 复测](../acceptance/VIDEO-SUMMARY-AGENT-PLANNING-20261013.md)：本地实际局部截图正确，但出现跨图描述复用和漏看结尾；云端三图观察及调查结束通过。两者最终都在章节生成阶段失败，没有完整总结。此次未触发 JSON 结构纠正，不能宣称该分支已实测通过；章节候选与逐条审核原因未留存，尚不能确定最终章节为空的具体原因。
